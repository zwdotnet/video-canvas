## 1. 目标与范围

用户上传的素材、生成结果和画布文件由 NAS 长期保存。只在模型请求实际需要外部 URL 时，将这次用到的本地参考素材临时放到 Cloudflare R2，再让上游拉取。现有画布继续使用 `/files/<storage_key>`。首版覆盖走连镜协议插件的生图和视频任务，按**每个文件引用**选择发送方式。同一请求可以混用 URL 和内联文件。

| 场景 | 预期行为 |
| --- | --- |
| 本地素材，插件要求 `url` | 校验归属，检查 R2 临时对象，缺失时上传，生成限时 GET 签名链接 |
| 本地素材，插件要求 `dataUrl`、`base64` 或 multipart 文件 | 从 NAS 读取，照现有格式发送 |
| 已有外部地址或命中渠道备案 | 沿用官方素材公网地址或插件支持的 `asset://` |
| 上传、生成落盘、预览与下载 | 使用 NAS 默认存储及素材登记的原文件位置，保留素材 ID、对象路径和画布链接 |

## 2. 开发设计

**接入位置**。在 Go 宿主 [插件文件引用解析](../../backend/internal/provider/plugin/executor.go#L1019) 里，保留备案优先级，只给 `as: "url"` 的本地素材增加签名 URL 准备逻辑。其他分支继续使用 [素材读取](../../backend/internal/service/asset.go#L240) 和现有大小限制。用协议引用的实际 `as` 字段判断，保留插件在准备阶段上传并转换为上游文件 ID 的能力。宿主在本次请求实际发出前解析和签名，核对准备结果重用和提交重试路径。遵循 [后端依赖组装](../../backend/internal/initialize/app.go#L159)，复用存储注册表和现有 S3 客户端。

**配置**。增加独立开关、目标存储 ID、临时对象前缀、签名时长和容量上限。默认关闭，部署通过后端配置指定已建立的私有 R2 配置。目标存储与默认写入存储分别配置。复用连镜保存的桶凭证，签名使用 HTTPS GET。对启用但目标无效、缺少写权限或无法签名的情况，返回可定位的错误。凭证、完整签名 URL 和文件内容从日志及试跑详情脱敏。

**临时对象**。使用专属前缀 `ref-cache/`。用源存储 ID、素材路径及内容摘要识别同一份数据。无摘要的旧素材从本地流式计算摘要。只准备插件真正引用的文件，同一请求中的重复引用只处理一次。用 `HeadObject` 检查候选对象的存在性、大小和摘要元数据。仅把明确的 404 当作缺失。首次上传用条件写或同等原子去重机制，统一处理重复任务和并发写入。给 R2 检查与上传设独立的准备超时，用现有任务截止时间约束总预算，避免参考文件上传占完上游提交窗口。准备失败沿用现有任务错误和重试机制，区分尚未发出生成请求与提交结果未知。

**保留与清理**。候选值为签名最长 24 小时，任务完成且最近使用满 3 天后清理，R2 的 `ref-cache/` 前缀设置 7 天删除规则作为兜底。上线前用各 URL 渠道的实际排队、任务最长运行时间和重试窗口确认这些值。复用对象时检查剩余寿命能否覆盖本次窗口，临近生命周期截止的对象改用新对象。保存任务对临时对象的使用记录，进程重启后仍可查询。在对象上还有其他活跃任务时保留对象。`submit_unknown` 保留到约定宽限时间，已超时或取消但无法确认上游停下的任务也按此处理。遇到规则配置变更，先确认它只覆盖临时前缀。

**容量与异常恢复**。初始拟设临时对象在管容量上限 **5 GB**，上线时按 R2 账户其他用途调整。容量计入已确认对象和正在上传的预留，多个 worker 通过持久化记录协调。超出上限时先回收符合条件的对象，仍不足就让本次 URL 准备失败并提示原因。上传响应丢失、崩溃和删对象失败等情况需要定期按临时前缀对账，确认对象确实不存在后再释放相应容量。清理失败重试，避免由旧清理任务删掉刚被重新租用的对象。记录命中数、上传字节、容量、失败分类和清理结果。R2 账单以账户用量为准，5 GB 是应用控制值。 [R2 计量与免费额度](https://developers.cloudflare.com/r2/pricing/#free-tier) · [R2 生命周期](https://developers.cloudflare.com/r2/buckets/object-lifecycles/) · [预签名 URL](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)

## 3. 实施顺序

1. **固定行为契约**。先写定向测试，覆盖 URL 命中、缺失上传、内联直接读本地和同一请求混用。确认常用生图、视频插件走同一个宿主入口。
2. **实现云端准备服务**。加配置、权属检查、复用和容量预留，接入宿主 URL 分支。需要持久化时按仓库约定新增向前数据库迁移。用隔离的私有 R2 路径验证一次实际 PUT、GET、URL 签名和命中复用。
3. **实现回收和故障恢复**。补上活跃任务保护、未知提交结果宽限、并发占用和重启对账。把错误归类接入任务诊断，业务失败沿用现有积分处理。
4. **测试与试运行**。在测试环境让生图和视频分别走一次 URL 路径，验证上游确实拉取到参考素材。视频覆盖异步排队后拉取。再各跑一次现有的内联或直传路径，核对 R2 请求数没有增加，生成结果都落到本地。

## 4. NAS 切换与回滚

当前部署的 R2 存储配置是 `MyCF`（桶 `myh-r2`）。此前核验的 250 个素材都已指向 R2，NAS 上保留同路径副本。部署前重新盘点，覆盖这 250 个和此后新增的素材。

1. 切换前备份数据库和迁移清单。逐个校验 R2 主文件与 NAS 副本。R2 独有的对象先下载到原 `storage_key`，发现同路径但内容不一致时单独处理。
2. 暂停新任务或等进行中的写入完成。把新素材的默认存储设为 NAS，并只对校验通过的记录更新 `storage_id`。保留素材 ID 和 `storage_key`。最后再检查一次切换期间新增记录和进行中的上传。
3. 验证旧画布、预览和下载都能从 NAS 读取。启用 R2 临时文件功能，检查一个 URL 生图任务、一个 URL 视频任务和一个内联任务。确认临时对象进入 `ref-cache/`，产物写进 NAS。
4. 首轮发布保留桶内原来的素材副本，方便回滚。稳定后，独立确认可删清单，再处理这些历史副本。临时文件清理规则只覆盖 `ref-cache/`。
5. 出现故障时先关闭临时功能或退回旧镜像。若需要恢复此前的 R2 主存储方式，先确认原对象仍可读，把切换后仅存在 NAS 的新素材单独核对，再按清单恢复存储指向和默认值。回滚以保留升级期间新增的素材和项目数据为准。

## 5. 验收标准

- [ ] 同一素材反复作为 URL 输入时，R2 对象可复用，每次签名都有足够的剩余时长。并发缺失只产生一份有效临时对象，重复引用不重复上传。
- [ ] `dataUrl`、`base64` 和 multipart 使用本地字节，既有公网 URL 和备案引用继续可用。
- [ ] 视频在延迟拉取时能从 R2 读到参考文件。结束后按规则回收，清理期间仍被其他任务使用的文件可读。
- [ ] 403、上传超时、容量不足和素材缺失均有明确错误。未准备好引用时不会向上游提交生成任务。
- [ ] 并发上传、服务重启、删除失败和生命周期到期后的重新上传均通过定向测试。已有素材、他人素材和官方素材的权限行为符合现有契约。
- [ ] 迁回的历史素材与新生成的素材均从 NAS 提供。删除测试用的 R2 临时对象后，画布原文件仍可读取。功能关闭、回滚和恢复均有可复核记录。
